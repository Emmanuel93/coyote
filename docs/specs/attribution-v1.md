# Atribución v1 — regla R15

Estado: estable desde v0.1.0 · Implementación: `internal/attribution`, `coyote commit`, `coyote gate`, hook `commit-msg` · Decisión: ADR-0005 · Patrones: `standards/default/attribution.yaml`

Los ejemplos de abajo son literales a propósito. Este repo los excluye de R15 con un override visible en `coyote standards diff`.

## Regla

> R15 (MUST): ningún entregable lleva atribución a herramientas o modelos de IA.

Los commits, PRs, issues, releases y documentos son de la persona que los aprueba y firma con sus credenciales. Qué herramienta o agente ayudó queda en el ledger (`@ana/coyote-dev`, modelo, tokens, costo), que es donde se audita. No se escribe en el entregable.

## Qué cuenta como atribución

**Líneas completas** (se elimina la línea):

| id | Ejemplos |
|----|----------|
| coauthor-ai | `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` · `Co-authored-by: Copilot <…+Copilot@users.noreply.github.com>` · `Co-authored-by: Cursor Agent <cursoragent@cursor.com>` · `Co-authored-by: Amp <amp@ampcode.com>` |
| ai-session-trailer | `Claude-Session: …` · `Amp-Thread-ID: …` · `Cursor-Session: …` |
| generated-footer | `🤖 Generated with [Claude Code](https://claude.com/claude-code)` · `_Generated with […]_` · `> Generated by GitHub Copilot` · `<sup>Written by [Cursor Bugbot](…)</sup>` · `This PR was generated with […]` · `Desarrollado con Claude Code` |
| robot-emoji | una línea con 🤖 y el nombre de una herramienta o "generated" |
| ai-session-url | `claude.ai/code/session_…` · `app.devin.ai/sessions/…` · `chatgpt.com/codex/tasks/…` · `ampcode.com/threads/…` |
| ai-noreply | `noreply@anthropic.com` |

**Frases dentro de una línea útil**, siempre con el nombre de una herramienta:

| id | Ejemplo en un archivo | Resultado |
|----|------------------------|-----------|
| en-made-with-ai | `Refactor the parser (written with Claude Code).` | `Refactor the parser.` |
| es-hecho-con-ia | `Migración de esquema generada con Claude Code; revisada en QA.` | `Migración de esquema; revisada en QA.` |
| aider-prefix | `aider: fix parser` | `fix parser` |

En un archivo (`coyote attribution scrub`) la frase se quita y cada cambio se informa. En un mensaje de commit la frase **no se reescribe**: `coyote commit` y el hook detienen el commit y piden reescribirlo, para no cambiar en silencio el sentido de un asunto.

**Lo que no cuenta:**

- Personas: `Co-authored-by: Claude Dupont <claude@example.fr>`, `Haider Ali`, `Jules Verne`, o cualquier persona con correo de un proveedor. Los patrones exigen el correo o el nombre del bot, con límites de palabra.
- Hablar de las herramientas: "comparamos Copilot y Claude Code", "made by Claude Monet".
- Texto del producto sobre IA en general: "detectar imágenes generadas con IA" no nombra una herramienta.
- `cursor` y `devin` también son palabras y nombres: solo cuentan en trailers, pies y enlaces de sesión.

## Autoría

`coyote commit` también revisa la identidad con la que git haría el commit (`git var GIT_AUTHOR_IDENT` y `GIT_COMMITTER_IDENT`, que incluyen las variables `GIT_AUTHOR_*`). Si autor o committer son una herramienta (`Claude <noreply@anthropic.com>`, `Cursor Agent <cursoragent@cursor.com>`), el commit no se hace. `coyote doctor` lo revisa y el lint revisa autor y committer de cada commit del historial.

## Capas de defensa

| # | Capa | Dónde actúa | Qué hace |
|---|------|-------------|----------|
| 1 | Configuración del IDE | `.claude/settings.json`: `attribution.commit` y `attribution.pr` vacíos, `includeCoAuthoredBy: false` | la herramienta no agrega la firma |
| 2 | Gate `PreToolUse` | `coyote gate attribution` para `Bash` y las herramientas `mcp__*` | bloquea con código 2 un commit, tag, merge, PR, issue o comentario que la lleve |
| 3 | `coyote commit` | antes de `git commit` | revisa la autoría, quita las líneas, rechaza frases, registra un evento `attr` y hace el commit con la identidad de la persona |
| 4 | Hook `commit-msg` | en cada `git commit`, venga de donde venga | usa `coyote` si lo encuentra (PATH, `~/go/bin`, `/opt/homebrew/bin`, `/usr/local/bin`); si no, un filtro de líneas con `grep` que trata el mensaje como bytes |
| 5 | Lint y CI | `coyote standards lint` y `coyote attribution check --commits 50` | revisa `.md` y `.txt`, y mensaje, autor y committer de los commits desde que se adoptó coyote, merges incluidos |

Cada capa funciona sola; juntas cubren commits hechos por la persona, por el IDE o por un agente. Los merges hechos con el botón de GitHub no pasan por hooks locales: los detecta la capa 5.

## Gate para IDEs

`coyote gate attribution` lee de la entrada estándar el JSON del hook:

| Forma | Qué revisa |
|-------|------------|
| `tool_name` + `tool_input.command` (Claude Code, Codex) | el comando si publica un mensaje: `git commit/tag/notes/merge/revert/cherry-pick`, `gh pr/release/issue create/edit/comment/review/merge`, `gh api`, `glab mr/release/issue …` |
| `command` en la raíz (Cursor `beforeShellExecution`) | lo mismo |
| `toolName` + `toolArgs` como objeto o como JSON en texto (Copilot) | lo mismo |
| `command` como lista de argumentos | se une y se revisa igual |
| herramientas cuyo nombre habla de PR, commit, push de archivos, release, issue, comentario, revisión o merge (`mcp__github__create_pull_request`, `create_or_update_file`, `push_files`, `create_issue`…) | todos los textos de la entrada |
| texto que no es JSON | el texto, si parece un commit, tag o PR |

Además une las líneas partidas con `\` y lee los archivos de mensaje (`-F`, `--file`, `--body-file`), relativos al `cwd` del hook. Sale con 0 si pasa y con 2 y el motivo en stderr si bloquea; los IDEs le muestran ese motivo al agente para que corrija.

Límite conocido: revisa el comando completo, así que `sed -i "/noreply@anthropic.com/d" X.md && git commit …` se bloquea aunque el mensaje esté limpio. Basta con separar los dos comandos.

## Comandos

- `coyote attribution check [rutas] [--commits N] [--stdin]`: sin rutas revisa los mismos archivos que R15 en el estándar del proyecto, y los últimos 50 commits. Sale con 1 si encuentra algo, incluido un clon superficial que no deja revisar el historial.
- `coyote attribution scrub [archivo] [--in-place] [--commit-msg]`: limpia un archivo o la entrada estándar. Con `--commit-msg` (el modo del hook) no toca los comentarios de git salvo los que son atribución, se detiene ante una frase y sale con 1 si el mensaje queda vacío (git aborta el commit).

## Excepciones por proyecto

`allow_paths` del default solo contiene `**/testdata/**`. Un proyecto excluye otras rutas con un override de R15 que exige motivo y queda a la vista:

```yaml
- id: R15
  override: { except: [docs/specs/attribution-v1.md], reason: "la spec cita los patrones como ejemplos", adr: ADR-0005 }
```

## Qué no hace

- No reescribe commits ya publicados. Si el lint encuentra atribución en el historial, la persona decide si reescribe su rama; coyote no fuerza pushes.
- No revisa código fuente: busca firmas en texto, no en literales de un programa.
- No oculta el uso de agentes: el ledger lo registra con actor, modelo, tokens y costo.

## Mantenimiento

Los patrones viven en `standards/default/attribution.yaml` con `id` y fragmentos compartidos en `vars`. Agregar una herramienta es agregar su correo, bot o dominio al patrón que corresponde, con un caso de prueba que la detecte y otro que confirme que no hay falso positivo con personas. El filtro básico del hook `commit-msg` se actualiza en la misma entrega.
